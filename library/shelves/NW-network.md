# NW · 네트워크·프로토콜

### NW-01 · TCP 연결과 지연
- 장면: 첫 요청만 느림 / 연결 수가 수만 개로 쌓임(TIME_WAIT).
- 이론: 3-way handshake = RTT 1번, 느린 시작, keep-alive와 커넥션 재사용, TIME_WAIT은 정상, Nagle·지연 ACK.
- 답해 볼 것: ① 새 연결 + TLS면 첫 바이트까지 RTT 몇 번 ② TIME_WAIT이 쌓이는 쪽 ③ keep-alive를 끄면
- 읽을 곳: HPBN 2장(TCP)
- 실습: 지연(`tc netem`) 50ms를 넣고 연결 재사용 유무로 요청 100개 시간 예측 후 측정
- 손으로: HTTP 클라이언트 커넥션 풀 설정
- 끝: 볼트에 3줄

### NW-02 · TLS
- 장면: 인증서 만료로 새벽 장애 / TLS 때문에 지연 증가.
- 이론: 핸드셰이크(1.2 vs 1.3), 인증서 체인, SNI, 세션 재개, 종료 지점(로드밸런서 vs 앱).
- 답해 볼 것: ① TLS 1.3이 빠른 이유 ② 체인이 빠지면 일부 클라이언트만 실패하는 이유 ③ 만료 감시 방법
- 읽을 곳: HPBN 4장(TLS)
- 실습: `openssl s_client`로 체인·버전 보기, 핸드셰이크 시간 측정
- 손으로: 인증서 만료 확인 스크립트
- 끝: 볼트에 3줄

### NW-03 · HTTP/1.1 · 2 · 3
- 장면: 작은 요청 수십 개가 느림 / HTTP/2로 바꿨는데 손실 많은 망에서 오히려 느림.
- 이론: HOL 블로킹(HTTP 층 vs TCP 층), 멀티플렉싱, 헤더 압축, QUIC(UDP 위, 연결 이전).
- 답해 볼 것: ① HTTP/2가 TCP HOL을 못 푸는 이유 ② QUIC이 푸는 것 ③ 서버 푸시가 사라진 이유
- 읽을 곳: HPBN 9~12장 · RFC 9114 개요
- 실습: 패킷 손실 1%·5%에서 HTTP/1.1 vs 2로 작은 파일 50개 받기
- 손으로: 결과 표
- 끝: 볼트에 3줄

### NW-04 · 실시간 연결: 폴링·SSE·WebSocket
- 장면: 알림 기능을 붙였더니 서버 연결 수가 폭증 / 로드밸런서가 60초마다 끊음.
- 이론: 롱폴링, SSE(단방향, HTTP), WebSocket(양방향), 유휴 타임아웃과 하트비트, 연결 수와 메모리, 스케일 아웃 시 브로드캐스트.
- 답해 볼 것: ① 서버→클라이언트만이면 무엇을 ② 연결 1만 개의 메모리 ③ 서버 여러 대에서 같은 방에 메시지 보내기
- 읽을 곳: HPBN 16장(SSE) · 17장(WebSocket)
- 실습: 연결 1만 개 붙여 메모리·CPU 예측 후 측정, 유휴 끊김 재현
- 손으로: 하트비트·재연결 로직
- 끝: 볼트에 3줄

### NW-05 · DNS와 로드밸런싱
- 장면: IP를 바꿨는데 일부 사용자는 몇 시간째 옛 서버로 / 서버 하나만 과부하.
- 이론: TTL과 캐시, L4 vs L7, 헬스 체크, 고정 세션, 연결 단위 vs 요청 단위 분산(gRPC 함정).
- 답해 볼 것: ① TTL을 낮춰도 바로 안 바뀌는 이유 ② gRPC가 L4에서 한 서버로 쏠리는 이유 ③ 헬스 체크가 너무 민감하면
- 읽을 곳: HPBN 1장 · Envoy 문서 "Load balancing"
- 실습: L4 vs L7 앞에서 HTTP/2 연결 분산 비교
- 손으로: 헬스 체크 엔드포인트 (무엇을 확인할지)
- 끝: 볼트에 3줄
