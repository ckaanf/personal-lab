# CC · 동시성 (JVM)

### CC-01 · 경쟁 조건과 가시성
- 장면: 카운터가 가끔 덜 올라감 / 다른 스레드가 바꾼 플래그를 못 봄.
- 이론: 원자성(check-then-act, read-modify-write)과 가시성(JMM, happens-before)은 다른 문제. `volatile`은 가시성만, `synchronized`·`Atomic*`은 둘 다.
- 답해 볼 것: ① `count++`가 원자적이지 않은 이유 ② `volatile`로 충분한 경우 ③ happens-before 규칙 두 개
- 읽을 곳: JCIP 2~3장 · JLS 17장(메모리 모델)
- 실습: 스레드 100개 × 1만 증가 → 결과값 예측 후 방식별(그냥 / volatile / synchronized / AtomicLong / LongAdder) 측정
- 손으로: check-then-act를 안전하게 고친 코드
- 끝: 볼트에 3줄

### CC-02 · 락과 데드락 (애플리케이션)
- 장면: 두 계좌 이체를 동시에 하면 멈춤.
- 이론: 락 순서, `tryLock` 타임아웃, 락 범위 줄이기, 스레드 덤프로 데드락 찾기.
- 답해 볼 것: ① 이체에서 락 순서를 정하는 법 ② `ReentrantLock`이 필요한 때 ③ 스레드 덤프에서 볼 줄
- 읽을 곳: JCIP 10장
- 실습: 데드락 만들기 → `jstack`으로 찾기 → 고치기
- 손으로: 계좌 ID 순서로 락 잡는 이체
- 끝: 볼트에 3줄

### CC-03 · 스레드 풀과 큐
- 장면: 비동기 작업이 쌓여 메모리 부족 / 요청이 풀 대기에서 타임아웃.
- 이론: 코어·최대 크기, 큐 종류(무한 큐의 함정), 거절 정책, CPU 작업 vs I/O 작업의 풀 크기.
- 답해 볼 것: ① 무한 큐 + 최대 크기 설정의 함정 ② I/O 작업 풀 크기 정하기 ③ 거절 정책 4가지
- 읽을 곳: JCIP 8장 · `ThreadPoolExecutor` Javadoc
- 실습: 같은 작업을 풀 크기·큐 크기별로 → 처리량·대기 예측 후 측정
- 손으로: 상황에 맞는 풀 설정 하나와 이유
- 끝: 볼트에 3줄

### CC-04 · 가상 스레드
- 장면: Java 21로 올리며 가상 스레드를 켰더니 처리량이 기대만큼 안 오름 / 오히려 멈춤.
- 이론: I/O 대기가 많을 때 유리. 피닝(`synchronized` 안 블로킹, 네이티브), 풀링 대신 세마포어로 동시성 제한, ThreadLocal 비용.
- 답해 볼 것: ① 가상 스레드가 빠르지 않은 작업 ② 피닝이 생기는 조건 ③ DB 커넥션 풀과의 관계
- 읽을 곳: JEP 444
- 실습: I/O 대기 작업 1만 개를 플랫폼 스레드 풀 vs 가상 스레드로 → 시간·메모리 예측 후 측정, 피닝 재현(`-Djdk.tracePinnedThreads`)
- 손으로: 세마포어로 외부 호출 동시성 제한
- 끝: 볼트에 3줄

### CC-05 · 분산 락
- 장면: 서버 2대에서 같은 배치가 동시에 돎 / 선착순 쿠폰이 초과 발급.
- 이론: DB 락(`FOR UPDATE`, 유니크 제약), Redis 락(SET NX PX), 펜싱 토큰. 락이 풀린 뒤에도 일하는 프로세스(GC 멈춤) 문제.
- 답해 볼 것: ① 락 TTL이 일보다 짧으면 ② 펜싱 토큰이 막는 것 ③ 락 없이 유니크 제약으로 끝나는 경우
- 읽을 곳: DDIA 8장 "펜싱 토큰" · Martin Kleppmann "How to do distributed locking"(블로그)
- 실습: TTL보다 긴 작업 + 일부러 멈춤 → 중복 실행 수 측정, 펜싱으로 막기
- 손으로: 펜싱 토큰 비교 UPDATE
- 끝: 볼트에 3줄
