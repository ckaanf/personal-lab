# DOC · 인수인계·문서화

> "사람이든 에이전트든 이어받을 수 있게" — 지식이 한 사람에게 묶이지 않게 하는 서가.

### DOC-01 · 결정 기록 (ADR)
- 장면: 1년 전 왜 이렇게 만들었는지 아무도 모름 → 같은 논의를 또 함.
- 이론: 결정·맥락·대안·결과를 짧게, 결정마다 한 장, 바뀌면 새 장(덮어쓰지 않음).
- 답해 볼 것: ① ADR로 남길 만한 결정의 기준 ② "대안"을 적는 이유 ③ 코드 옆에 둘까 위키에 둘까
- 읽을 곳: Michael Nygard "Documenting Architecture Decisions"
- 실습: 개인 프로젝트에서 지난 결정 3개를 ADR로 → 6개월 뒤의 내가 이해할지 다른 세션 AI에게 읽혀 확인
- 손으로: ADR 한 장
- 끝: 볼트에 3줄

### DOC-02 · 런북
- 장면: 새벽 경보, 담당자가 아니면 무엇을 할지 모름.
- 이론: 경보 하나에 런북 하나, 확인 → 완화 → 확인 순서, 명령은 복사해서 바로 쓰게, 정기적으로 실행해 보며 갱신.
- 답해 볼 것: ① 좋은 런북의 첫 줄 ② 런북이 낡았는지 아는 법 ③ 자동화할 단계와 사람이 판단할 단계
- 읽을 곳: SRE Workbook "On-Call" 장
- 실습: 홈서버 장애 하나의 런북을 쓰고, 그 런북만 보고 다른 세션 AI가 복구하게 해 보기
- 손으로: 런북 한 장
- 끝: 볼트에 3줄

### DOC-03 · 온보딩 문서
- 장면: 새 사람(또는 새 AI 세션)이 처음 일주일을 질문으로 보냄.
- 이론: 먼저 읽을 것 3개, 지도(무엇이 어디에), 첫 작업 하나, 문서는 질문이 나올 때마다 고친다.
- 답해 볼 것: ① 첫날 반드시 알아야 할 것 ② 문서가 아닌 코드로 보여 줄 것 ③ 낡지 않게 하는 장치
- 읽을 곳: Diátaxis 문서 체계(tutorial·how-to·reference·explanation)
- 실습: 개인 레포 하나의 README만으로 새 세션 AI가 첫 작업을 끝내는지 → 막힌 곳을 문서에 반영
- 손으로: README 하나
- 끝: 볼트에 3줄

### DOC-04 · 에이전트가 읽는 지침
- 장면: AI 세션마다 같은 설명을 반복 / 지침이 길어져 아무도 안 읽음.
- 이론: 사람용 문서와 에이전트용 지침의 차이, 규칙은 한 곳에, 이유를 같이, 짧게 유지.
- 답해 볼 것: ① 사람 문서를 그대로 쓰면 안 되는 이유 ② 규칙이 두 곳에 있으면 ③ 지침을 줄이는 기준
- 읽을 곳: AI 서가 AI-01 카드
- 실습: 지침 파일 하나를 절반으로 줄이고 같은 작업 결과 비교
- 손으로: 줄인 지침
- 끝: 볼트에 3줄
