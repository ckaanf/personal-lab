# OP · 운영·관측·장애

> 깊게: [운영·복구 실험실](../labs/ops-recovery/README.md) — 홈서버(homelab)를 무대로.

### OP-01 · 로그·메트릭·트레이스
- 장면: 장애가 났는데 어느 서비스에서 시작됐는지 30분째 찾는 중.
- 이론: 메트릭은 "무엇이", 로그는 "왜", 트레이스는 "어디서". 구조화 로그, 상관 ID, 카디널리티 폭발.
- 답해 볼 것: ① 요청 하나를 서비스 3개에 걸쳐 따라가려면 ② 메트릭 라벨에 사용자 ID를 넣으면 ③ 로그 레벨을 운영에서 바꾸는 법
- 읽을 곳: SRE 6장(분산 시스템 모니터링) · OpenTelemetry 문서 "Observability primer"
- 실습: 서비스 2개 + 트레이스 수집 → 일부러 넣은 지연을 트레이스로 찾기
- 손으로: 상관 ID를 로그에 넣는 필터
- 끝: 볼트에 3줄

### OP-02 · SLO와 경보
- 장면: 경보가 하루 50개라 아무도 안 봄 / 진짜 장애는 사용자가 먼저 알림.
- 이론: SLI·SLO·에러 버짓, 증상 기반 경보(원인 기반 X), 번 레이트 경보.
- 답해 볼 것: ① 가용성 99.9%면 한 달 허용 시간 ② CPU 경보가 나쁜 경보인 이유 ③ 번 레이트 경보 두 창의 의미
- 읽을 곳: SRE 4장(SLO) · SRE Workbook 5장(SLO 기반 경보)
- 실습: 내 서비스 하나의 SLI 정하고 지난 한 달 값을 계산
- 손으로: 경보 규칙 하나
- 끝: 볼트에 3줄

### OP-03 · 백업과 복구
- 장면: 백업은 매일 돌았는데 복원해 보니 깨져 있음 / 백업이 원본과 같은 디스크에.
- 이론: 3-2-1, RPO·RTO, 복원 리허설 없는 백업은 백업이 아니다, 논리 백업 vs 물리 백업, 시점 복구(PITR).
- 답해 볼 것: ① 내 데이터의 RPO·RTO ② 디스크 하나가 죽으면 무엇을 잃나 ③ 복원을 언제 마지막으로 해 봤나
- 읽을 곳: PostgreSQL 문서 "Backup and Restore" · SQLite "Backup API"
- 실습: 백업 → 다른 곳에서 복원 → 데이터 비교, 걸린 시간 예측 후 측정
- 손으로: 복원 확인 스크립트 (행 수·체크섬 비교)
- 끝: 볼트에 3줄

### OP-04 · 배포와 롤백
- 장면: 배포 직후 오류율 상승, 되돌리는 데 20분.
- 이론: 롤링·블루그린·카나리, DB 마이그레이션은 롤백이 어렵다(확장-축소 패턴), 기능 플래그.
- 답해 볼 것: ① 컬럼 이름을 무중단으로 바꾸는 단계 ② 롤백이 안 되는 변경 ③ 카나리 판단 지표
- 읽을 곳: Martin Fowler "BlueGreenDeployment" · "Parallel Change"
- 실습: 확장-축소로 컬럼 바꾸기를 구버전·신버전 동시 실행 중에
- 손으로: 마이그레이션 단계 표
- 끝: 볼트에 3줄

### OP-05 · 장애 대응과 회고
- 장면: 장애 중 여러 명이 동시에 다른 걸 고침 / 회고가 "조심하자"로 끝남.
- 이론: 지휘자·소통·기록 역할, 완화가 원인 분석보다 먼저, 비난 없는 회고, 재발 방지는 사람이 아니라 장치로.
- 답해 볼 것: ① 장애 중 첫 10분에 할 일 ② "조심하자"가 재발 방지가 아닌 이유 ③ 좋은 액션 아이템의 조건
- 읽을 곳: SRE 14장(장애 관리) · 15장(포스트모템 문화)
- 실습: 지난 장애 하나를 양식대로 다시 써 보기 (회사 일은 일반화해서)
- 손으로: 회고 양식
- 끝: 볼트에 3줄

### OP-06 · 리눅스 문제 찾기 60초
- 장면: 서버가 느린데 무엇부터 볼지 모름.
- 이론: `uptime`, `dmesg`, `vmstat`, `mpstat`, `pidstat`, `iostat`, `free`, `sar -n DEV`, `sar -n TCP`, `top` — 순서와 각각 보는 숫자.
- 답해 볼 것: ① load average가 높은데 CPU가 놀면 ② `free`의 available ③ TCP 재전송이 늘면
- 읽을 곳: Netflix Tech Blog "Linux Performance Analysis in 60,000 Milliseconds"
- 실습: CPU·디스크·메모리·네트워크 부하를 하나씩 넣고 어떤 명령에서 보일지 예측
- 손으로: 내 서버용 점검 명령 묶음
- 끝: 볼트에 3줄
