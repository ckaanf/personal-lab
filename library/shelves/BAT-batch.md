# BAT · 배치·대량 처리

### BAT-01 · 청크 처리와 커밋 단위
- 장면: 100만 건 배치가 중간에 실패, 처음부터 다시 돌리니 중복.
- 이론: 읽기·처리·쓰기를 청크로, 청크마다 커밋, 청크 크기와 락·메모리·재시작의 맞교환.
- 답해 볼 것: ① 청크 1 vs 1만의 차이 ② 한 건 실패하면 청크 전체는 ③ 커서 vs 페이징 읽기
- 읽을 곳: Spring Batch 문서 "Chunk-oriented Processing"
- 실습: 청크 크기별 처리 시간·DB 부하 예측 후 측정
- 손으로: 청크 처리 루프(프레임워크 없이)
- 끝: 볼트에 3줄

### BAT-02 · 재시작과 멱등
- 장면: 실패한 배치를 다시 돌려도 되는지 확신이 없음.
- 이론: 어디까지 했는지 기록, 다시 돌려도 결과가 같게(upsert·처리 표시), 건너뛰기·재시도 정책.
- 답해 볼 것: ① 재시작 위치를 어디에 저장하나 ② 외부 호출이 섞인 배치의 재시작 ③ 건너뛴 건을 다루는 법
- 읽을 곳: Spring Batch 문서 "Configuring a Step for Restart" · TX-03 카드
- 실습: 중간에 강제 종료 → 재시작 후 중복·누락 0 확인
- 손으로: 처리 표시 컬럼 + upsert
- 끝: 볼트에 3줄

### BAT-03 · 배치와 온라인 트래픽 공존
- 장면: 새벽 배치가 늦어져 아침 서비스 시간과 겹치면서 API가 느려짐.
- 이론: 읽기 복제본, 속도 조절(throttle), 작은 트랜잭션, 락 순서, 인덱스 영향, 시간대 분리.
- 답해 볼 것: ① 배치가 온라인을 느리게 하는 경로 3개 ② 속도를 어떻게 정하나 ③ 배치용 인덱스의 비용
- 읽을 곳: DB-03·DB-05 카드
- 실습: 배치를 돌리며 API p99 측정 → 속도 조절로 영향 줄이기
- 손으로: 속도 조절 로직
- 끝: 볼트에 3줄

### BAT-04 · 스케줄링과 중복 실행 방지
- 장면: 서버 두 대에서 같은 배치가 동시에 돎.
- 이론: cron vs 스케줄러, 분산 락(CC-05), 리더 선출, 실행 이력과 알림.
- 답해 볼 것: ① 서버가 늘면 cron이 문제 되는 이유 ② 배치가 안 돌았다는 걸 아는 법 ③ 겹쳐 실행되면
- 읽을 곳: ShedLock README
- 실습: 인스턴스 3개에서 같은 스케줄 → 중복 수 측정 → 락으로 1로
- 손으로: "안 돌았음" 알림 규칙
- 끝: 볼트에 3줄
