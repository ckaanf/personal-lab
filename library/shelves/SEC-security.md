# SEC · 보안 기초

### SEC-01 · 인증과 세션·토큰
- 장면: 로그아웃했는데 토큰이 계속 통함 / 토큰이 로그에 남음.
- 이론: 세션 vs JWT, 만료·갱신 토큰, 폐기 문제, 저장 위치(쿠키 HttpOnly·SameSite vs 로컬 저장소).
- 답해 볼 것: ① JWT를 즉시 무효화하려면 ② 갱신 토큰 탈취를 알아채는 법(회전) ③ 로그에 남기면 안 되는 것
- 읽을 곳: OWASP Cheat Sheet "Session Management" · "JSON Web Token for Java"
- 실습: 갱신 토큰 회전 + 재사용 감지 구현해 탈취 시나리오 재현
- 손으로: 토큰 검증 필터
- 끝: 볼트에 3줄

### SEC-02 · 인가와 IDOR
- 장면: URL의 주문 번호를 바꾸니 남의 주문이 보임.
- 이론: 인증 ≠ 인가. 객체 단위 권한 검사, 서비스 계층에서 검사, 목록 조회의 필터 누락.
- 답해 볼 것: ① 컨트롤러에서만 검사하면 ② 관리자 기능 분리 ③ 권한 검사 누락을 테스트로 찾기
- 읽을 곳: OWASP API Security Top 10 "BOLA"
- 실습: 일부러 IDOR가 있는 API → 테스트로 찾고 고치기
- 손으로: 소유자 검사
- 끝: 볼트에 3줄

### SEC-03 · 주입과 입력 검증
- 장면: 검색어에 따옴표를 넣었더니 500 / 정렬 파라미터로 SQL 주입.
- 이론: 바인딩 변수, 동적 정렬·컬럼명은 허용 목록, 경로 조작, SSRF(서버가 대신 요청).
- 답해 볼 것: ① `ORDER BY ?`가 안 되는 이유와 대안 ② SSRF로 클라우드 메타데이터를 읽는 경로 ③ 검증을 어디서
- 읽을 곳: OWASP Cheat Sheet "SQL Injection Prevention" · "SSRF Prevention"
- 실습: 주입이 있는 쿼리 3개를 찾아 고치기
- 손으로: 정렬 허용 목록
- 끝: 볼트에 3줄

### SEC-04 · 비밀 관리
- 장면: API 키가 깃 기록에 남음 / 로그에 DB 비밀번호.
- 이론: 환경 변수 vs 비밀 저장소, 회전, 깃 기록에서 지워도 이미 유출, 사전 커밋 검사.
- 답해 볼 것: ① 유출된 키를 발견하면 첫 순서 ② 회전이 쉬운 구조 ③ 로그 마스킹
- 읽을 곳: OWASP Cheat Sheet "Secrets Management" · gitleaks README
- 실습: 일부러 넣은 가짜 키를 gitleaks로 잡기
- 손으로: 사전 커밋 훅
- 끝: 볼트에 3줄
