# SR · 검색

### SR-01 · 역색인
- 장면: `LIKE '%키워드%'`가 너무 느림.
- 이론: 단어 → 문서 목록, 색인 시점 분석과 검색 시점 분석, 세그먼트와 병합, 거의 실시간(refresh).
- 답해 볼 것: ① LIKE 앞 와일드카드가 인덱스를 못 타는 이유 ② refresh 간격의 의미 ③ 삭제가 바로 사라지지 않는 이유
- 읽을 곳: Elasticsearch 문서 "Near real-time search" · 『Lucene in Action』 개념 장
- 실습: 100만 문서에서 LIKE vs 전문 검색 시간 예측 후 측정
- 손으로: 아주 작은 역색인 (Map<단어, List<문서>>)
- 끝: 볼트에 3줄

### SR-02 · 한국어 분석
- 장면: "삼성전자"로는 나오는데 "삼성"으로는 안 나옴.
- 이론: 형태소 분석(nori), n-gram, 사용자 사전, 동의어, 색인·검색 분석기를 다르게.
- 답해 볼 것: ① n-gram의 대가 ② 사전에 없는 신조어 ③ 동의어를 색인 때 vs 검색 때
- 읽을 곳: Elasticsearch 문서 "Nori analysis plugin"
- 실습: 같은 문장을 분석기 3가지로 쪼개 결과 비교, 검색 누락 사례 고치기
- 손으로: 분석기 설정
- 끝: 볼트에 3줄

### SR-03 · 점수와 정렬
- 장면: 검색 결과 순서가 이상하다는 민원.
- 이론: TF-IDF·BM25, 필드 가중치, 함수 점수(최신·인기), 필터는 점수에 안 들어감.
- 답해 볼 것: ① BM25가 문서 길이를 다루는 방식 ② 필터와 쿼리의 차이 ③ 최신 글을 위로 올리는 법
- 읽을 곳: Elasticsearch 문서 "Practical BM25"(블로그 시리즈)
- 실습: `explain`으로 점수 분해 → 가중치를 바꿨을 때 순위 변화 예측
- 손으로: 함수 점수 쿼리
- 끝: 볼트에 3줄

### SR-04 · DB와 검색 엔진 동기화
- 장면: DB에서는 수정됐는데 검색 결과는 옛 내용.
- 이론: 이중 쓰기 vs 아웃박스 vs CDC(TX 서가와 같은 문제), 전체 재색인과 별칭 전환.
- 답해 볼 것: ① 이중 쓰기 실패 시 ② 무중단 재색인 순서 ③ 동기화 지연 허용치
- 읽을 곳: TX-05 카드 · Elasticsearch 문서 "Aliases"
- 실습: CDC로 동기화하고 지연 측정, 별칭 전환으로 재색인
- 손으로: 재색인 절차
- 끝: 볼트에 3줄
