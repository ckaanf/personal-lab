### AI-01 · 지침 계층과 컨텍스트
- 장면: 지침에 적은 규칙을 에이전트가 어김 / 대화가 길어지면 처음 규칙을 잊음.
- 이론: 사용자·프로젝트·폴더 지침의 계층, 컨텍스트 창은 유한하고 앞부분이 요약된다, 메모리는 다음 세션용, 규칙은 짧고 검증 가능하게.
- 답해 볼 것: ① 지침이 길어지면 생기는 일 ② "하지 마"보다 "장치로 막기"가 나은 규칙 ③ 메모리와 지침 파일의 역할 차이
- 읽을 곳: Claude Code 문서 "Memory" · "Settings"
- 실습: 지침 길이 3단계로 같은 작업 → 규칙 준수율·토큰 예측 후 측정
- 손으로: 내 지침 파일에서 지울 줄 고르기
- 끝: 볼트에 3줄

### AI-02 · 막는 장치: 권한·훅·샌드박스
- 장면: 에이전트가 위험한 명령을 실행할 뻔함 / "커밋하지 마"를 어김.
- 이론: 부탁(지침) < 확인(권한 묻기) < 막기(deny 규칙·훅·샌드박스). 훅은 도구 호출 전후에 사람이 정한 검사를 끼운다.
- 답해 볼 것: ① 지침으로 충분한 규칙 vs 훅이 필요한 규칙 ② 훅이 실패하면 ③ 샌드박스가 막는 것
- 읽을 곳: Claude Code 문서 "Hooks" · "IAM / permissions"
- 실습: `git push`를 막는 훅을 만들고 에이전트에게 push를 부탁해 보기
- 손으로: 훅 스크립트
- 끝: 볼트에 3줄

### AI-03 · 검증: 테스트 먼저, 새 세션 리뷰
- 장면: 에이전트가 "다 됐어요"라고 했는데 안 됨 / 자기 코드를 자기가 리뷰하면 다 통과.
- 이론: 완료 기준을 먼저 테스트로, 같은 세션의 자기 선호 편향, 새 세션(또는 다른 모델)에 결론 없이 코드만 주기, 불변식 기반 확인.
- 답해 볼 것: ① 같은 세션 리뷰가 놓치는 것 ② 리뷰어에게 무엇을 주고 무엇을 숨기나 ③ "통과"를 믿을 수 있는 조건
- 읽을 곳: Anthropic "Building effective agents"(블로그)
- 실습: 버그를 심은 코드를 같은 세션 vs 새 세션에 리뷰시켜 발견률 비교
- 손으로: 리뷰 요청 프롬프트 한 장
- 끝: 볼트에 3줄

### AI-04 · 서브에이전트와 병렬
- 장면: 에이전트 여러 개를 돌렸더니 토큰만 들고 결과는 비슷.
- 이론: 서브에이전트가 이득인 때(독립 작업, 넓은 탐색, 결론만 필요) vs 손해(맥락 전달 손실, 같은 일 반복). 위임 프롬프트에 목표·제외한 것·범위.
- 답해 볼 것: ① 위임하면 잃는 것 ② 병렬이 의미 있는 작업 모양 ③ 위임 결과를 믿기 전에 확인할 것
- 읽을 곳: Claude Code 문서 "Subagents"
- 실습: 같은 조사를 혼자 vs 서브에이전트 3개로 → 토큰·시간·정확도 비교
- 손으로: 위임 프롬프트 양식
- 끝: 볼트에 3줄

### AI-05 · 스킬·플러그인으로 반복 일 묶기
- 장면: 같은 설명을 매번 다시 함.
- 이론: 반복되는 절차를 스킬(지시서 + 스크립트)로, 팀 배포는 플러그인으로. 스킬은 짧게, 판단은 사람에게 남기기.
- 답해 볼 것: ① 스킬로 만들 만한 반복의 조건 ② 스킬이 너무 많으면 ③ 스킬이 잘 작동하는지 재는 법
- 읽을 곳: Claude Code 문서 "Skills" · "Plugins"
- 실습: 자주 하는 일 하나를 스킬로 → 전후 걸린 시간·수정 횟수
- 손으로: 스킬 문서 한 장
- 끝: 볼트에 3줄
