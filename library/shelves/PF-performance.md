# PF · 성능·부하

### PF-01 · 지연은 평균이 아니라 분위수
- 장면: 평균 50ms인데 사용자는 느리다고 함.
- 이론: p50·p95·p99, 꼬리 지연, 여러 호출을 거치면 꼬리가 커진다(fan-out). 좌표 누락(coordinated omission).
- 답해 볼 것: ① 하위 호출 10개를 병렬로 부르면 전체 p99는 ② 평균이 속이는 예 ③ 부하 도구가 좌표 누락을 만드는 경우
- 읽을 곳: Gil Tene "How NOT to Measure Latency"(발표) · DDIA 1장 "성능 기술하기"
- 실습: 지연 분포가 다른 하위 3개 → fan-out 전체 p99 예측 후 측정
- 손으로: 분위수 계산 함수
- 끝: 볼트에 3줄

### PF-02 · 부하 테스트 설계
- 장면: 부하 테스트는 통과했는데 운영에서 터짐.
- 이론: 열린 모델(도착률) vs 닫힌 모델(가상 사용자), 워밍업, 실제 데이터 분포, 목표(SLO)부터 정하기.
- 답해 볼 것: ① VU 100과 초당 100요청의 차이 ② 워밍업을 빼면 ③ 테스트 데이터가 작으면
- 읽을 곳: k6 문서 "Scenarios" · "Open and closed models"
- 실습: 같은 서버를 열린/닫힌 모델로 → 포화 지점 예측 후 측정
- 손으로: 시나리오 하나 (목표·단계·합격 기준)
- 끝: 볼트에 3줄

### PF-03 · 포화와 대기열 (리틀의 법칙)
- 장면: CPU는 40%인데 응답이 느림.
- 이론: L = λW. 사용률이 높아지면 대기 시간은 비선형으로 증가. 병목은 CPU가 아니라 풀·락·커넥션일 수 있다. USE 방법(사용률·포화·오류).
- 답해 볼 것: ① 처리량 200/s, 평균 0.5초면 동시 처리 중 요청 수 ② 사용률 90%의 대기 ③ CPU 외 포화 신호
- 읽을 곳: Brendan Gregg "The USE Method"
- 실습: 부하를 올리며 처리량·지연 곡선, 꺾이는 지점 예측
- 손으로: 내 서비스의 자원별 USE 표
- 끝: 볼트에 3줄

### PF-04 · JVM 메모리와 GC
- 장면: 주기적으로 응답이 1초씩 멈춤 / 컨테이너가 OOMKilled.
- 이론: 힙·메타스페이스·다이렉트 메모리, 컨테이너 메모리 한도와 `MaxRAMPercentage`, G1/ZGC 멈춤, GC 로그 읽기.
- 답해 볼 것: ① 힙 < 컨테이너 한도인데 OOMKilled ② G1 vs ZGC 고르는 기준 ③ GC 로그에서 볼 숫자
- 읽을 곳: Oracle "HotSpot GC Tuning Guide"
- 실습: 할당 많은 작업 → GC별 멈춤 시간 분포 측정
- 손으로: 컨테이너용 JVM 옵션 한 세트와 이유
- 끝: 볼트에 3줄
