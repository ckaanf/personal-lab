# JVM · JVM 내부

> 성능 서가 PF-04(GC) 다음 단계.

### JVM-01 · 클래스 로딩과 시작 시간
- 장면: 스프링 앱이 뜨는 데 40초 / 같은 클래스인데 `ClassCastException`.
- 이론: 로딩 → 링크 → 초기화, 클래스 로더 계층, 시작 시간의 대부분(클래스 로딩·리플렉션·빈 생성), CDS·AOT.
- 답해 볼 것: ① 같은 이름 클래스가 다른 타입이 되는 경우 ② 시작 시간을 재는 법 ③ CDS가 줄이는 것
- 읽을 곳: JVM 명세 5장 · Spring Boot 문서 "Efficient deployments"(CDS)
- 실습: `-Xlog:class+load`로 로딩 수, CDS 켜고 끈 시작 시간 예측 후 측정
- 손으로: 시작 시간 측정 스크립트
- 끝: 볼트에 3줄

### JVM-02 · JIT와 워밍업
- 장면: 배포 직후 몇 분간만 느림 / 마이크로 벤치마크 결과가 이상함.
- 이론: 인터프리터 → C1 → C2, 인라이닝, 탈최적화, 워밍업, 죽은 코드 제거로 벤치마크가 거짓말함.
- 답해 볼 것: ① 배포 직후 느린 이유 ② 벤치마크에 JMH가 필요한 이유 ③ 탈최적화가 일어나는 경우
- 읽을 곳: JMH 샘플 코드 · Aleksey Shipilёv 블로그 글들
- 실습: 같은 코드를 순진한 루프 vs JMH로 재서 차이 보기, 워밍업 전후 지연 곡선
- 손으로: JMH 벤치마크 하나
- 끝: 볼트에 3줄

### JVM-03 · 바이트코드와 프록시
- 장면: `@Transactional`을 붙였는데 같은 클래스 안 호출에서 안 먹음.
- 이론: 바이트코드 기초, 동적 프록시(JDK vs CGLIB), 스프링 AOP가 동작하는 범위, self-invocation.
- 답해 볼 것: ① self-invocation이 프록시를 우회하는 이유 ② final 메서드에 AOP가 안 되는 이유 ③ `javap -c`로 볼 것
- 읽을 곳: Spring 문서 "Understanding AOP Proxies"
- 실습: self-invocation 재현 → 프록시 클래스 이름 출력으로 확인
- 손으로: JDK 동적 프록시로 만든 아주 작은 트랜잭션 흉내
- 끝: 볼트에 3줄

### JVM-04 · 진단 도구
- 장면: 운영 서버가 멈췄는데 무엇을 떠야 할지 모름.
- 이론: 스레드 덤프(`jstack`), 힙 덤프(`jmap`·HPROF), JFR(항상 켜 두는 기록), `jcmd`.
- 답해 볼 것: ① 멈췄을 때 스레드 덤프를 몇 번, 몇 초 간격으로 ② 힙 덤프의 운영 부담 ③ JFR로 볼 수 있는 것
- 읽을 곳: Oracle "Troubleshooting Guide" · JDK Mission Control
- 실습: 일부러 만든 메모리 누수·락 경합을 JFR로 찾기
- 손으로: 장애 시 덤프 뜨는 스크립트
- 끝: 볼트에 3줄
