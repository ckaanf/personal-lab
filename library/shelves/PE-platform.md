# PE · 플랫폼 엔지니어링·개발 환경

> "사람이 기억해서 맞추는 것"을 "장치가 맞춰 주는 것"으로 바꾸는 서가. 공통 개발환경·인프라·설정.

### PE-01 · 로컬 재현성
- 장면: "제 PC에서는 되는데요" / 새로 온 사람이 첫 실행까지 이틀.
- 이론: 런타임 버전 고정(mise·asdf·`.tool-versions`), 의존 서비스는 compose로, 한 명령으로 띄우기, 비밀은 예시 파일만 저장소에.
- 답해 볼 것: ① 버전이 어긋나는 지점 3곳 ② "한 명령"에 들어가야 할 것 ③ 비밀을 저장소 밖에 두면서 쉽게 시작하는 법
- 읽을 곳: mise 문서 · "The Twelve-Factor App" II. Dependencies
- 실습: 깨끗한 컨테이너에서 연습 프로젝트를 처음부터 띄우는 시간 측정 → 막힌 곳을 없애고 다시 측정
- 손으로: `make dev`(또는 스크립트) 하나
- 끝: 볼트에 3줄

### PE-02 · 템플릿과 골든 패스
- 장면: 서비스마다 로깅·설정·빌드 방식이 다 다름.
- 이론: 새 서비스 템플릿, 기본으로 따라오는 것(로그 형식·헬스 체크·지표·CI), 강제가 아니라 가장 쉬운 길로.
- 답해 볼 것: ① 템플릿에 넣을 것과 뺄 것 ② 템플릿이 낡는 문제 ③ 기존 서비스를 맞추는 순서
- 읽을 곳: Spotify Engineering "How We Use Golden Paths to Solve Fragmentation"
- 실습: 연습 프로젝트 둘의 차이 목록 → 템플릿으로 하나 만들기 → 새 서비스 시작 시간 비교
- 손으로: 템플릿 체크리스트
- 끝: 볼트에 3줄

### PE-03 · CI 표준
- 장면: 빌드가 20분 / 테스트가 가끔 깨져서 다들 재실행만 함.
- 이론: 빠른 피드백 순서(린트 → 단위 → 통합), 캐시, 흔들리는 테스트 격리, 필수 검사.
- 답해 볼 것: ① 빌드 시간의 대부분이 어디인지 재는 법 ② 흔들리는 테스트를 다루는 규칙 ③ 필수 검사로 둘 것
- 읽을 곳: GitHub Actions 문서 "Caching dependencies" · Google Testing Blog "Flaky Tests at Google"
- 실습: 연습 레포 CI 단계별 시간 측정 → 캐시·병렬로 줄이기
- 손으로: CI 설정 하나
- 끝: 볼트에 3줄

### PE-04 · 설정과 환경 관리
- 장면: 운영 설정 하나가 빠져 배포 직후 장애 / 설정이 어디에 있는지 아무도 모름.
- 이론: 설정의 출처 한 곳, 환경별 차이만 덮어쓰기, 시작할 때 검증(fail fast), 설정 변경도 코드 리뷰.
- 답해 볼 것: ① 필수 설정이 없으면 언제 알아채나 ② 환경별 차이를 최소로 ③ 설정 변경 이력
- 읽을 곳: Spring Boot 문서 "Externalized Configuration" · "@ConfigurationProperties 검증"
- 실습: 필수 설정을 빼고 띄웠을 때 실패 시점을 바꿔 보기(런타임 → 시작 시)
- 손으로: 설정 검증 클래스
- 끝: 볼트에 3줄

### PE-05 · 개발자 경험 재기
- 장면: 개선했다는데 정말 나아졌는지 모름.
- 이론: 리드 타임, 배포 빈도, 변경 실패율, 복구 시간(DORA), 첫 실행까지 시간, 빌드 대기 시간.
- 답해 볼 것: ① 지금 숫자를 어디서 가져오나 ② 사람을 재는 지표가 되면 생기는 일 ③ 처음 잴 하나
- 읽을 곳: DORA "Four Keys"
- 실습: 개인 레포들에서 리드 타임·배포 빈도를 깃 기록으로 계산
- 손으로: 계산 스크립트
- 끝: 볼트에 3줄
