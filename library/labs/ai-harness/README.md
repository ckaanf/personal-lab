# AI 하네스 실험실 — 부탁하지 말고 막고, 믿지 말고 재기

> 서가: [AI 서가](../../shelves/AI-harness.md). 실습은 이 레포의 작은 연습 프로젝트(예: `spring-lab/payment-consistency`) 위에서.
> 이미 매일 쓰는 방식(지침 계층, 메모리, 스킬, 플러그인)을 **숫자로** 확인하는 연습.

## 끝난 기준
1. 질문마다 볼트 `Notes/실험기록/`에 3줄 (`library: AI-0N`).
2. "이 규칙은 지침 / 권한 / 훅 중 어디에 두나" 판단 기준 한 장 (내 말로).
3. 측정 표 하나: 같은 작업을 방식별로 했을 때 토큰·시간·결과 품질.

## 이론 : 실습 = 3 : 7
도구 문서는 짧고 바뀌기 쉬워서, 실습으로 확인하는 비중을 높인다. 다만 측정 방법(무엇을 성공으로 볼지)은 실습 전에 정한다.

## 질문
| # | 질문 | 이론 먼저 | 실습 (예측 → 측정) | 손으로 |
|---|---|---|---|---|
| 1 | 지침은 얼마나 지켜지나? | 지침 계층, 컨텍스트 요약 | 규칙 10개 지침으로 작업 20번 → 준수율, 지침 길이별 비교 | 지울 규칙 고르기 |
| 2 | 막아야 할 규칙은? | 권한 deny, 훅, 샌드박스 | push 금지·특정 폴더 쓰기 금지를 지침 vs 훅으로 → 위반 수 | 훅 스크립트 |
| 3 | 토큰은 어디로 가나? | 컨텍스트 구성(지침·도구 결과·대화) | 같은 작업의 토큰 내역을 읽고 큰 항목 3개 줄이기 | 줄인 전후 표 |
| 4 | "다 됐다"를 어떻게 믿나? | 테스트 먼저, 불변식 | 완료 기준 테스트 유무로 같은 작업 → 실제 통과율 | 완료 기준 테스트 |
| 5 | 리뷰는 누가 하나? | 자기 선호 편향 | 버그 심은 코드: 같은 세션 vs 새 세션 리뷰 발견률 | 리뷰 요청 양식 |
| 6 | 나눠 맡기면 이득인가? | 위임 비용 | 같은 조사를 혼자 vs 서브에이전트 3개 → 토큰·시간·정확도 | 위임 프롬프트 양식 |
| 7 | 반복 일을 묶으면? | 스킬·플러그인 구조 | 자주 하는 일 하나를 스킬로 → 전후 시간·수정 횟수 | 스킬 문서 |

## 주의
- 회사 일은 이 레포로 가져오지 않는다. 실험은 이 레포의 연습 프로젝트로만.
- 측정 숫자는 모델·버전에 따라 바뀐다. 기록에 날짜와 모델을 같이 적는다.
