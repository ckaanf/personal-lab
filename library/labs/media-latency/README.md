# 미디어 지연 실험실 — 구간마다 재고, 줄이고, 맞춘다

> 서가: [MD 서가](../../shelves/MD-media.md). 코드는 `media-lab` 레포. 볼트의 Media-Lab 질문 목록(지연·모션·동기화)과 같은 질문을 이론과 함께 깊게.
> 목표는 플랫폼 완성이 아니라 "내 파이프라인의 지연이 어디서 몇 ms인지 설명할 수 있다".

## 끝난 기준
1. 질문마다 볼트 `Notes/실험기록/`에 3줄 (`library: MD-0N`).
2. 내 파이프라인의 **구간별 지연 표** (예측 vs 실제).
3. 글 1편: 구간 하나의 숫자를 줄인 이야기.

## 이론 : 실습 = 5 : 5
미디어는 개념(코덱·버퍼·프로토콜)을 모르면 숫자를 읽을 수 없어서 이론 비중을 높인다.

## 질문
| # | 질문 | 이론 먼저 | 실습 (예측 → 측정) | 손으로 |
|---|---|---|---|---|
| 1 | 끝단 지연은 몇 초인가? | 파이프라인 구간, 타임코드 측정법 | 화면 타임코드를 찍어 송신·수신 화면을 함께 촬영 | 측정 방법 메모 |
| 2 | 어느 구간이 가장 큰가? | 인코딩·세그먼트·버퍼 | 구간마다 시계 찍기, 예측 표와 비교 | 구간 로그 형식 |
| 3 | 인코딩 설정으로 얼마나 줄이나? | GOP, B 프레임, preset, zerolatency | 설정 조합별 지연·CPU·화질 표 | 저지연 옵션 세트 |
| 4 | 세그먼트 방식의 바닥은? | HLS/LL-HLS, 세그먼트 길이 | 세그먼트 6·2·1초와 부분 세그먼트 비교 | 결과 표 |
| 5 | WebRTC로 바꾸면? | UDP, 지터 버퍼, SFU | 같은 소스 WebRTC 전송, `webrtc-internals` 읽기 | 관찰 지표 5개 |
| 6 | 망이 나쁘면? | 손실·지터, NACK·FEC | `tc netem` 손실 1·5%, 지터 30ms → 멈춤·지연 | 결과 표 |
| 7 | 웹캠 얼굴 움직임을 보내면 지연은? | 데이터 채널, 직렬화 크기 | 모션 데이터 전송 지연과 크기 측정 | 메시지 형식 |
| 8 | 영상과 모션을 어떻게 맞추나? | RTP 타임스탬프, 공통 시계 | 둘의 어긋남 측정 → 동기화 버퍼로 맞추기 | 동기화 버퍼 |
