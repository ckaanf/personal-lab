# 운영·복구 실험실 — 홈서버를 무대로

> 서가: [OP 서가](../../shelves/OP-operations.md). 무대는 이 레포의 `homelab/`(운영 문서 원본 `homelab/OPERATIONS.md`).
> "돌아가고 있다"가 아니라 "망가져도 몇 분 안에 되돌린다"를 증명하는 연습.

## 끝난 기준
1. 질문마다 볼트 `Notes/실험기록/`에 3줄 (`library: OP-0N`).
2. 복구 리허설 기록 1회: 서버 밖 백업에서 재정·식단 기록을 다른 곳에 복원하고 걸린 시간을 잰다.
3. `homelab/OPERATIONS.md`에 RPO·RTO 표와 복구 절차가 있다.

## 이론 : 실습 = 4 : 6

## 질문
| # | 질문 | 이론 먼저 | 실습 (예측 → 측정) | 손으로 |
|---|---|---|---|---|
| 1 | 디스크 하나가 죽으면 무엇을 잃나? | 3-2-1, RPO·RTO | 지금 데이터·설정 목록과 위치 표, 잃는 것 예측 | 데이터 목록 표 |
| 2 | 백업은 정말 복원되나? | 논리 vs 물리 백업, SQLite 온라인 백업 | 백업 → 다른 곳에 복원 → 행 수·체크섬 비교, 시간 측정 | 복원 확인 스크립트 |
| 3 | 백업을 서버 밖에 두려면? | 암호화, 보존 기간, 비용 | 서버 밖 저장 1곳 붙이고 자동화, 실패 시 알림 | 백업 스크립트 실패 처리 |
| 4 | 무엇이 죽으면 내가 먼저 알까? | SLI, 증상 기반 경보 | 서비스별 SLI 정하고 업타임 경보가 실제로 오는지 일부러 죽여 보기 | 경보 규칙 |
| 5 | 서버가 느릴 때 무엇부터 보나? | 리눅스 60초 점검 | CPU·디스크·메모리·네트워크 부하를 하나씩 넣고 명령별로 보일지 예측 | 점검 명령 묶음 |
| 6 | 배포가 반영됐는지 어떻게 아나? | 배포본 = 저장소, 드리프트 | 손 배포 누락을 일부러 만들고 점검 스크립트로 잡기 | `check.sh` 한 줄 |
| 7 | 서버를 새로 만들어야 하면 몇 분? | 설정의 코드화, 재현성 | 새 VM(또는 컨테이너)에 처음부터 올리는 리허설, 시간 측정 | 막힌 곳 목록 |

## AI에게 맡기는 것 / 내가 하는 것
- AI: 스크립트 초안, 장애 주입 방법, 측정 정리.
- 나: 무엇을 잃어도 되는지(RPO), 복원 리허설 실행과 판단, 비밀 값 다루기(AI는 키·토큰 파일을 읽지 않는다).
