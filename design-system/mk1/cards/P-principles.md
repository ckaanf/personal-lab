# P · 원칙

다른 카드끼리 부딪히거나 카드에 없는 상황이면 여기서 판단한다.

### P-01 · 여러 연령대가 기준
- 하는 일: 누구를 기준으로 크기·대비·표시 방식을 고르는지 정한다.
- 규칙: 본문 글자는 14px 아래로 내리지 않는다(작은 보조 글자도 12px까지). 회색 글자도 흰 바탕 대비 4.5:1 이상. 아이콘에는 늘 이름을 붙인다. 색만으로 뜻을 나누지 않는다(점 + 글자, C-03).
- 끝: 가장 흐린 글자색의 대비를 재서 4.5 이상인지, 화면에서 이름 없는 아이콘이 0개인지.
- 왜: 13px 회색 안내 글이 대비 3.3:1이었고 11px 글자가 섞여 있었다. 만든 사람 화면에서는 멀쩡해 보여도 고객 모니터에서는 안 읽혔다.
- 이어짐: T-01, T-02, C-03, Q-05

### P-02 · 같은 일은 같은 자리에서 같은 모양으로
- 하는 일: 화면이 늘어나도 한 번 배운 것으로 다른 화면을 쓰게 한다.
- 규칙: 상세 화면은 모두 같은 틀(L-05). 할 일·단계·상태·입력 칸·카드 모양은 화면마다 다르게 만들지 않는다. 같은 동작은 같은 버튼 이름(W-03).
- 끝: 상세 화면들을 나란히 놓고 "머리 줄 / 단계 줄 / 할 일 / 카드 / 오른쪽 칸"을 표로 비교해 다른 칸이 0개인지.
- 왜: 상세 화면 셋이 따로 자라자 할 일이 한 화면에서는 세 곳에 나뉘고, 카드 모양이 세 가지, 상태 표시가 두 가지가 됐다. 나란히 비교하는 점검으로 한 번에 8곳이 나왔다.
- 이어짐: L-05, X-04

### P-03 · 보는 사람 기준으로 "지금 할 일" 하나
- 하는 일: 사용자가 화면을 열자마자 내가 무엇을 해야 하는지 알게 한다.
- 규칙: "우리 차례 / 상대 차례" 같은 관계 말 대신 할 일 자체(동사)를 보인다. 내가 할 일은 진하게, 상대가 하는 일은 회색, 끝난 것은 완료 색. 주 버튼은 그 할 일 하나(C-01).
- 끝: 아무 상세 화면을 열어 3초 안에 할 일 문장과 버튼 하나를 찾을 수 있는지.
- 왜: 같은 화면을 두 쪽이 보는데 "우리 차례"가 상대 화면에서도 "우리 차례"로 보이는 결함이 있었다. 할 일을 동사로 바꾸자 문제가 사라졌다.
- 이어짐: L-05, C-03, W-02

### P-04 · 쓴 것은 잃지 않는다
- 하는 일: 사용자가 적은 글이 어떤 경우에도 사라지지 않게 한다.
- 규칙: 화면을 다시 그리기·폴링·로그인 끊김·메뉴 이동·새로고침 모두 "적던 글이 남는가"를 따진다. 잃을 수 있는 곳은 보관(초안)하거나 떠나기 전에 묻는다.
- 끝: F-01의 확인 순서를 돌린다.
- 왜: "작성하던 내용이 사라졌다"는 사용자 지적이 첫 실패였다. 원인을 따라가 보니 같은 종류가 다섯 군데 더 있었다.
- 이어짐: F-01, F-02, Q-03

### P-05 · 기본값은 안전한 쪽
- 하는 일: 실수했을 때 피해가 작은 쪽을 기본으로 둔다.
- 규칙: 공개 / 비공개가 갈리면 비공개가 기본이고, 공개로 고르면 "○○에게 보입니다"를 띄운다. 즉시 저장되는 고르기 칸은 되돌릴 수 없으면 쓰지 않는다. 지우기·공개·내보내기는 확인을 받는다.
- 끝: 아무것도 고치지 않고 보내기만 눌렀을 때 바깥에 보이는 것이 없는지.
- 왜: 내부 메모와 상대에게 가는 답글이 체크박스 하나로 갈렸고 기본값이 공개였다. 체크를 잊으면 내부 사정이 그대로 나갔다.
- 이어짐: C-06, F-02

### P-06 · 시안 먼저, 숫자로 전후
- 하는 일: 만들기 전에 합의하고, 만든 뒤 나아졌는지 숫자로 본다.
- 규칙: 큰 화면 변화는 "지금 / 바뀐 뒤" 시안(X-03)을 먼저 보여 주고 승인 뒤 만든다. 시작 전에 기준선(클릭 수, 카드 수, 걸리는 곳 수)을 재고 끝나면 다시 잰다.
- 끝: 결과 기록에 전·후 숫자가 둘 다 있는지.
- 왜: "어수선하다"는 느낌을 "오른쪽 카드 8개 → 정보 칸 하나", "단순 요청 하나 끝내는 데 클릭 12번"처럼 세자 무엇을 고칠지 바로 정해졌다.
- 이어짐: X-03, X-04
