# W · 문구

### W-01 · 버튼은 짧은 동사
- 하는 일: 버튼 이름만 보고 누르면 무슨 일이 생기는지 알게 한다.
- 규칙: 동사 하나(또는 목적어 + 동사). 괄호 설명을 붙이지 않는다. 같은 동작은 어디서나 같은 이름.
- 예: ✗ "개발로 (진행 요청)" → ✓ "진행 요청" / ✗ "고치기"와 "수정하기"가 섞임 → ✓ "수정하기" 하나
- 끝: 화면 전체 버튼 이름을 뽑아 같은 동작에 다른 이름이 있는지.
- 이어짐: C-01, W-03

### W-02 · 상태는 이름 하나
- 하는 일: 상태 표시를 한 단어로 읽히게 한다.
- 규칙: 상태 두 개를 점으로 이어 붙이지 않는다. 지금 가장 중요한 것 하나만.
- 예: ✗ "회신함 · 상대 차례" → ✓ "상대 확인 중"
- 이어짐: C-03, P-03

### W-03 · 같은 것은 같은 말
- 하는 일: 용어가 갈려 사용자가 "둘이 다른 건가?" 하지 않게 한다.
- 규칙: 프로젝트마다 용어표를 하나 두고 화면·문서·알림에 똑같이 쓴다. 비슷한 말(의견 / 회신 / 답, 보내기 / 담기)은 뜻을 갈라 정해 두고 섞지 않는다. 내부 용어(묶음·판·차수 같은 우리끼리 말)는 바깥 사용자 화면에 내보내지 않는다.
- 끝: 바깥 사용자 계정으로 돌며 내부 용어가 0개인지.
- 왜: 내부 분류 이름이 바깥 사용자 화면에 그대로 보였고, "대신 기록 — 수정 요청"과 "대신 기록: 수정 요청"처럼 같은 버튼이 두 모양이었다.

### W-04 · 안내 글은 막힐 곳에만 한 줄
- 하는 일: 안내 글이 화면을 덮지 않게 한다.
- 규칙: 버튼 이름으로 알 수 있으면 쓰지 않는다. 처음 보는 사람이 실제로 막히는 곳에만 한 줄. 긴 대시·화살표·괄호 덧붙임 금지. 숫자로 알릴 수 있으면 숫자(버튼 옆 "담긴 3").
- 예: ✗ "담기 — 위 보내기로 함께 나갑니다" → ✓ 버튼 "담기" + 보내기 옆 담긴 수
- 늘 보이는 개발자용 안내(명령어 등)는 설정 화면으로 옮기고 그 자리엔 링크 한 줄.
