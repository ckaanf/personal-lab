# F · 동작

화면 모양이 아니라 "어떻게 움직여야 하는가". 부품과 함께 부탁한다(예: "C-06 + F-02").

### F-01 · 다시 그려도 적던 글은 남는다
- 하는 일: 폴링·실시간 갱신·저장 신호로 화면을 다시 그릴 때 입력을 지킨다.
- 생김새: "조용한 다시 그리기" — 불러오는 중 화면을 거치지 않고, 손댄 칸의 값·체크·고른 것·초점·커서·스크롤을 새 화면으로 옮긴다. 다시 그리는 사이에 친 글자도 옮긴다.
- 규칙: 손으로 고친 칸은 서버 값보다 내 글이 이긴다. 적는 중인 칸은 "적는 중" 표시를 두고, 저장되면 표시를 지운다.
- 끝(확인 순서): ① 칸에 글을 적고 스크롤을 내려 둔 채 갱신을 일으킨다 → 글·커서·스크롤 그대로, 깜빡임 없음 ② 로그인이 끊기게 한 뒤 다시 로그인 → 적던 글이 남고 원래 화면으로 돌아옴 ③ 새로고침·메뉴 이동 → 남거나, 떠나기 전에 묻는다.
- 왜: 작업이 도는 동안 3초마다 화면 전체를 다시 그려 적던 글이 사라졌다. 같은 원인이 메모 칸, 새 요청 양식, 로그인 끊김에서도 나왔다.
- 이어짐: P-04, F-02, Q-03

### F-02 · 초안과 보내기를 나눈다
- 하는 일: 저장(잃지 않기)과 보내기(상대에게 알리기)를 다른 일로 다룬다.
- 생김새: 몇 초 쉬면 자동으로 **나만 보는 초안** 저장(이력에 남기지 않음). [저장] [보내기] 버튼. 위 띠에 "보내지 않은 내용 있음 · 초안 저장 시각". 목록에 "보내지 않음" 표시와 "작성한 N건 보내기".
- 규칙: 상대에게는 보낸 것만 보인다. 보내기 한 번 = 이력 한 줄. 보내지 않은 채 떠나면 묻는다(머물기 / 초안으로 두고 이동 / 보내고 이동). 창을 닫으면 브라우저가 묻는다. 오래된 초안을 저절로 보내지는 않는다.
- 보내지 않은 초안 알리기: 적은 사람에게는 윗줄 "보내지 않은 초안 N건" + 첫 화면 목록(무엇·날짜·N일째·열기·한 번에 보내기). 상대에게는 "작성 중 · 보내기 전 · N일째"만(내용은 보내야 보임).
- 왜: 입력이 0.6초 멈출 때마다 저장하고 이력을 남겨서 메모 한 줄에 이력 수십 줄이 쌓였다. 반대로 사람들은 적어 두기만 하고 보내기를 잊었다.
- 이어짐: C-06, F-01, P-04

### F-03 · 새 소식과 읽음
- 하는 일: 보낸 사람은 상대가 봤는지, 받는 사람은 무엇이 새로 왔는지 안다.
- 규칙: 읽음은 "그 화면을 열었다"로 센다(짧은 시간 묶음). 보낸 글 밑에 "아직 안 읽음 → 읽음 · 시각". 상대 글과 목록 줄에 "새로". 처음 들어온 사람에게는 최근 N일 것만 새 소식. 소식(새로 온 것)과 할 일(누가 해야 하는 것)은 다른 표시로 둔다.
- 끝: 두 계정·두 브라우저로 한쪽에서 보내고 다른 쪽 🔔 점과 "새로"를 보고, 연 뒤 보낸 쪽이 "읽음 · 시각"으로 바뀌는지.
- 이어짐: C-11, C-07, L-01

### F-04 · 찾기
- 하는 일: 번호나 제목 글자로 어디서든 바로 간다.
- 규칙: 아무 화면에서 `/` 로 찾기 칸에 초점(글 칸에 적는 중이면 제외). 번호 · 제목 글자로 찾고 ↑↓ · Enter로 연다. 권한 밖 결과는 보이지 않는다(없는 것처럼). 결과가 없으면 "없음" 한 줄.
- 이어짐: L-01

### F-05 · 동시 수정은 칸마다 다르게
- 하는 일: 두 사람이 같은 것을 고칠 때 잃는 것을 줄인다.
- 규칙: 
  - 목록형(핀·댓글 여럿): 전체를 덮어쓰지 않고 "더한 것 / 지운 것"만 보낸다 → 둘 다 남는다.
  - 키-값형(질문별 답): 바뀐 키만 보낸다. 같은 키를 그 사이 남이 고쳤으면 마지막 저장이 이기고 이력에 "덮어씀 + 이전 값".
  - 값 하나(상태·메모): 마지막 저장 + "덮어씀" 기록.
  - 판정은 칸마다 버전 번호(`base_rev`)로. 상대가 고친 것은 주기적으로 확인해 "○○이 고쳤습니다 [다시 불러오기]".
- 포기해도 되는 것: 글자 단위 동시 편집. 잦아지면 "지금 누가 보고 있음" 표시가 먼저다.

### F-06 · 되돌릴 수 없는 일은 한 번 더
- 하는 일: 실수로 생기는 중복·공개·삭제를 막는다.
- 규칙: 건드리면 바로 저장되는 고르기 칸은 되돌릴 수 있을 때만. 일괄 바꾸기는 실패하면 알린다. 보내는 중에는 버튼을 막아 두 번 가지 않게. 실패 뒤 다시 누를 때 같은 것이 두 번 생기지 않게(서버에서 같은 요청 거르기). 바뀐 것 없이 보내면 "바뀐 것이 없습니다"로 막는다(기록·알림이 쌓이지 않게).
- 왜: 첨부 올리기가 실패하면 접수 버튼이 다시 살아나 같은 요청이 두 번 생겼다. 바뀐 것 없이 보낸 요청이 같은 기록·새 소식을 쌓았다.
- 이어짐: C-01, P-05

### F-07 · 끝까지 단계로 추적
- 하는 일: 요청이 어디까지 갔는지 처음부터 끝까지 한 줄로 보인다.
- 규칙: 단계는 이름 있는 목록(예: 논의 중 › 진행 요청 › 진행 확정 › 개발 중 › 개발 완료 › 검토 › 반영 완료, 옆길 보류·제외). 단계를 손으로 건너뛰지 못하게 하거나, 건너뛰면 빠진 확인을 묻는다. 바깥 사용자에게는 바깥용 단계 이름만, 내부 번호·주소는 숨긴다. 갈림길(다시 확인 / 진행)은 사람이 고르는 단계로 화면에 둔다.
- 이어짐: L-05(단계 줄), P-03
