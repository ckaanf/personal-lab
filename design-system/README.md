# design-system

웹과 앱에 같이 쓰는 내 디자인 시스템. **뼈대(카드 · 부품 · 동작)는 하나, 값(색 · 둥글기 · 글자)은 프리셋으로 여러 벌**. 보는 틀(룩북)과 부르는 이름도 하나다.

- **mk1** — 뼈대 + 기본 값. 2026-10 협의 포털에서 겪은 고민을 일반화했고, 개인 재정 앱 시험(`mk1/trials/`)에서 빈 폰 앱 부품 8개를 더했다. 여러 연령대 기준. 카드 59 · 예시 36.
- **mk2** — mk1 뼈대 위의 프리셋. 개인 앱 공통 디자인 v0.1 의 값(종이 · 남색 · 모서리 20 · 제목 글꼴 Do Hyeon), 대비 4.5 에 못 미치던 색 셋(보조 회색 · 주황 · 완료 초록)만 진하게 맞췄다.

왜 이렇게: 시험해 보니 개인 앱과 업무 포털의 차이는 거의 값이었고(프리셋 CSS 한 장으로 대비 미달 16 → 0), 뼈대가 다른 시스템을 섞어 쓰면 클래스 이름이 겹쳤다(2026-10-30 결정).

## 여는 법

```bash
python3 -m http.server 8791 --directory ~/Personal/project/personal-lab/design-system
```

`http://127.0.0.1:8791` → 룩북. 파일을 바로 열면(file://) 예시 iframe 이 막히니 서버로 연다.

- **룩북(대시보드)**: 시스템 고르기 → 블록 목록(묶음으로 거르기, `/` 찾기) → 블록 상세(살아 있는 예시 · 밝게/어둡게 · 데스크톱/폰 · 카드 전문).
- **부품 한 장 보기 + 조종 패널**: `mk1/kit.html`. 토큰을 움직여 보고 [tokens.json 복사] → `mk1/tokens.json` 에 붙여 넣고 빌드.

## 부탁하는 법

부르는 이름은 모든 시스템이 같다: **`시스템_카드ID`**. 룩북의 [부탁 복사]가 이 문장을 클립보드에 넣는다.

- "**mk1_C-03 구현해줘**" → 카드의 생김새·상태·규칙·토큰대로 만들고, `끝` 항목으로 확인한 결과를 보고한다.
- "**mk1_L-04 + mk1_F-02 로 폰 화면**" → 여러 카드를 한 화면으로. 카드끼리 부딪히면 그 시스템의 P 카드로 판단하고 무엇을 골랐는지 말한다.
- "**mk1_C-03 을 SwiftUI로**" → 토큰 이름과 규칙은 그대로, 모양만 그 플랫폼 관례로.
- "**mk2_C-13 구현해줘**" → mk1 의 C-13 카드대로 만들고 값은 mk2 토큰을 쓴다.
- 카드에 없는 것이 필요하면 만들기 전에 "카드에 없음: ○○" 한 줄로 묻는다. 새 판단이 정해지면 카드를 더한다.

## 폴더

```
design-system/
  index.html              룩북(모든 시스템 공통 틀, mk1 로 그림)
  lookbook/               룩북 스크립트·스타일, catalog.js(빌드가 만듦)
  tools/build.py          tokens.json → tokens.css·tokens.js, cards/*.md → catalog.js
  mk1/
    system.json           이름·설명·묶음 이름·견본 색
    cards/*.md            블록 카드(규칙 원본은 여기 한 곳)
    tokens.json           토큰 원본(플랫폼 중립). tokens.css·tokens.js 는 빌드 결과
    components.css        부품 · 틀. 클래스는 모두 ds- 로 시작(기존 앱 CSS 와 섞여도 안 겹치게)
    mk1.js                부품 동작(아이콘, 보기 설정 기억, 고르기·접기·메뉴·서랍·찾기·복사)
    examples.js           블록 예시 — ex('C-03', ...) 가 있으면 룩북에 "예시 있음"
    examples.html         예시 하나(룩북이 iframe 으로 부름) · kit.html 부품 한 장 + 조종 패널
                          둘 다 ?preset=mk2 면 그 시스템 값으로 그린다
    trials/               다른 앱에 입혀 본 시험 기록
  mk2/
    system.json           "base": "mk1" — 카드 · 부품 · 예시는 mk1 것을 쓴다. fontCss 로 글꼴을 부른다
    tokens.json           값만. mk1 과 같은 토큰 이름
  mock/lookbook-v1.html   승인된 시안(2026-10-30)
```

카드·토큰·예시를 고친 뒤에는 `python3 tools/build.py`.

## 범례 — 카드 묶음

| 기호 | 묶음 | 담는 것 |
|---|---|---|
| P | 원칙 | 판단 기준. 다른 카드가 막힐 때 여기로 돌아온다 |
| W | 문구 | 버튼·상태·안내 글을 쓰는 규칙 |
| T | 토큰 | 색·글자·둥글기·간격·높이의 역할과 단계 |
| C | 부품 | 버튼, 상태 표시, 입력, 카드, 표, 말풍선, 창 |
| L | 틀 | 윗줄, 왼쪽 메뉴, 폰 탭 줄·서랍, 상세 화면 틀 |
| F | 동작 | 잃지 않기, 초안·보내기, 알림·읽음, 찾기, 동시 수정 |
| X | 도구 | 조종 패널, 부품 한 장 보기, 시안 비교, 점검표 |
| Q | 함정 | 실제로 겪은 깨짐과 막는 법. 만들고 나서 대조한다 |

## 카드 양식

```
### C-03 · 상태 표시
- 하는 일: 이 블록이 해결하는 것 한 줄
- 생김새: 무엇으로 이루어지나(안쪽 부품 순서)
- 상태: 기본 / 올림 / 고름 / 막힘 / 비었음 / 불러오는 중 / 오류 중 해당하는 것
- 규칙: 지켜야 할 것. "~하지 않는다"까지
- 토큰: 쓰는 토큰 이름(T 카드)
- 모두를 위해: 여러 연령대·접근성 조건
- 끝: 다 됐는지 확인하는 방법(눈으로 / 키보드로 / 숫자로)
- 왜: 이 규칙이 나온 장면(일반화)
- 이어짐: 같이 쓰는 카드 ID
```

`### ID · 이름` 머리와 `- 키: 값` 줄을 빌드가 읽는다. 들여 쓴 줄은 앞 칸에 이어 붙는다.

## 새 프리셋 더하기

`mkN/system.json`(`"base": "mk1"`)과 `mkN/tokens.json`(mk2 를 복사해 값만 바꾼다)을 만들고 빌드하면 룩북에 나온다. 값은 `mk1/kit.html?preset=mkN` 조종 패널에서 움직여 보고 복사한다.
뼈대가 정말 다른 시스템이 필요할 때만 `base` 없이 카드 · 부품 · 예시를 따로 둔다.
